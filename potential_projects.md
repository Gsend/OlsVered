While Deep Learning usually relies on First-Order methods (like SGD or Adam) to avoid the \(O(n^3)\) cost of matrix inversion, there are specific architectures and hybrid techniques where OLS-style inversion is the primary bottleneck.Here are the key usages where matrix inversion (specifically for solving OLS or regularized OLS) is a significant portion of the training cost:1. K-FAC (Kronecker-factored Approximate Curvature)K-FAC is a Second-Order optimization method that approximates the Fisher Information Matrix.The Usage: Instead of just using gradients, it calculates the "curvature" of the loss landscape.The Inversion Cost: It involves inverting many smaller matrices (factors) for every layer of the network. In large Transformers or CNNs, these inversions are so expensive that they are typically only performed every 100 or 1000 iterations to keep the training time manageable.2. Differentiable Convex Optimization Layers (OptNet)Some models incorporate a Quadratic Programming (QP) solver directly into the neural network's forward pass.The Usage: Used in robotics and control systems where the output must satisfy physical constraints (e.g., "don't hit the wall").The Inversion Cost: Backpropagating through these layers requires solving a system of linear equations (essentially inverting the KKT matrix). This is the dominant cost of the entire forward and backward pass.3. Ridge Regression Heads (Freeze-and-Solve)In Transfer Learning or Few-Shot Learning, developers often freeze a large backbone (like a ResNet or Vision Transformer) and only train a new linear head.The Usage: Instead of using SGD to train the last layer, you treat it as an OLS/Ridge Regression problem and solve it analytically using the Normal Equation: \(\beta = (X^T X + \lambda I)^{-1} X^T y\).The Inversion Cost: If the "embedding" size (\(X\)) is large (e.g., 2048 or 4096 dimensions), the \(O(F^3)\) cost of inverting the \(X^{T}X\) matrix becomes the slowest part of the adaptation process.4. Echo State Networks (ESN) & Liquid State MachinesThese are types of Reservoir Computing where the internal weights are random and fixed; only the "readout" layer is trained.The Usage: Training the readout layer is almost always done via a single OLS solve.The Inversion Cost: Because the reservoir "state" can be very high-dimensional (thousands of neurons) to capture complex temporal patterns, the matrix inversion is effectively the only training cost, and it scales poorly as the reservoir size grows.5. Gaussian Processes (GPs) and Neural ProcessesGPs are used for uncertainty estimation and are often combined with Deep Learning (Deep GPs).The Usage: Training involves maximizing the marginal likelihood, which requires inverting the Kernel Matrix (\(K\)).The Inversion Cost: Standard GPs scale at \(O(N^3)\) where \(N\) is the number of data points. For large datasets, this is so prohibitive that "Sparse GPs" are used to reduce the matrix size.6. Unlike standard Deep Learning, where you take a small step down a hill (gradient descent), ALS tries to find the "perfect" bottom of the hill for one set of variables at a time.Here is why the inversion cost is so dominant in ALS training:1. The "Alternating" Solving LoopALS works by freezing the Item factors (\(Y\)) and solving for the User factors (\(X\)), then flipping and repeating. For every single user in your database, the algorithm must solve the Normal Equation:\(x_{u}=(Y^{T}C_{u}Y+\lambda I)^{-1}Y^{T}C_{u}p_{u}\)The Inversion: The \((Y^T C_u Y + \lambda I)^{-1}\) part is a matrix inversion of size \(F \times F\) (where \(F\) is the number of features).The Scale: If you have 10 million users, the computer performs 10 million matrix inversions in a single pass over the user set. It then does the same for all items.2. Why it’s the BottleneckIn typical neural networks, the bottleneck is usually Matrix Multiplication (\(O(n^2)\)). In ALS, the bottleneck is solving the linear system, which is effectively \(O(F^3)\).Small Feature Count (\(F < 64\)): The inversions are fast. Most of the time is spent moving data (I/O).Large Feature Count (\(F > 256\)): The cubic cost of the inversion takes over. Because you are doing millions of these \(O(F^3)\) operations, the training time explodes.3.
